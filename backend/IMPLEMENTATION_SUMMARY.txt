📦 WHAT WAS IMPLEMENTED
================================================================================

The custom_variants strategy allows API consumers to provide pre-defined query
variants WITHOUT any LLM enhancement. It leverages your existing RRF (Reciprocal
Rank Fusion) infrastructure for parallel search and result merging.

KEY FEATURES:
✅ Zero LLM cost (passthrough node - no AI enhancement)
✅ Full user control over query variants
✅ Automatic parallel vector search
✅ Automatic RRF fusion when multiple variants detected
✅ Flexible input formats (query as list OR base + custom_variants)
✅ Seamless integration with existing pipeline

🚀 HOW TO USE
================================================================================

WEBSOCKET API EXAMPLE:

# Option 1: Query as list (simplest)
{
    "query": [
        "SSL certificate configuration",
        "TLS settings and setup",
        "HTTPS encryption configuration"
    ],
    "conversation_id": "conv_123"
}

# Option 2: Base query + additional variants
{
    "query": "How to configure SSL?",
    "custom_variants": [
        "SSL certificate installation",
        "TLS setup guide"
    ],
    "conversation_id": "conv_123"
}

WHAT HAPPENS:
  1. custom_variants_node stores variants (no LLM calls)
  2. document_retriever detects multiple variants
  3. Auto-enables RRF (Reciprocal Rank Fusion)
  4. Parallel search across all variants
  5. RRF merges results by consensus
  6. Returns top_k fused documents

================================================================================
📊 STRATEGY COMPARISON
================================================================================

Strategy         | LLM | Variants | RRF | Cost | Control | Use Case
-----------------|-----|----------|-----|------|---------|------------------
native           | No  | 1        | No  | $0   | None    | Simple queries
augmented        | Yes | 4-5      | Yes | $$   | Low     | Max coverage
multi_query      | Yes | 5-6      | Yes | $$   | Low     | Alt phrasings
custom_variants  | No  | N        | Yes | $0   | Full    | User-defined

custom_variants = Native (no LLM) + Parallel Search + RRF Fusion

================================================================================
🎯 INTEGRATION FLOW
================================================================================

User sends variants → custom_variants_node (passthrough) →
document_retriever (detects variants) → parallel_retrieval (N searches) →
reciprocal_rank_fusion (merge) → Top K results

The custom_variants_node is SIMILAR TO NATIVE in that it does NO enhancement,
but it LEVERAGES RRF INFRASTRUCTURE by placing variants in augmented_queries
field, which triggers parallel search + fusion automatically.
