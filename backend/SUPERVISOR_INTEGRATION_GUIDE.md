# Supervisor Agent Integration Guide

## Overview
The supervisor agent needs to be updated to pass the correct embedding provider information when calling the MCP `knowledge_expert` tool.

## What Changed in MCP Tool

The `knowledge_expert` tool now requires **embedding provider information** from the agent's vector database collection configuration.

### New Required Parameters

```python
# These MUST be passed from agent's vector_database config
embedding_provider_id: str          # agent.vector_database.embedding_provider.id
embedding_model_name: str           # agent.vector_database.embedding_provider.model_name
vector_dimension: int               # agent.vector_database.vector_dimension
```

### Optional LLM Parameters

```python
# These are now optional (only used for reranking - already enabled)
llm_provider_id: str = ""           # agent.llm_provider.id (recommended)
llm_model_name: str = ""            # agent.llm_provider.model_name (recommended)
```

## Supervisor Agent Integration

### Step 1: Load Agent Configuration

Before calling the MCP tool, the supervisor must have access to the agent config:

```python
# Get the agent configuration
agent = get_agent(agent_id)  # From agent service

# Extract required embedding config
embedding_provider_id = agent.vector_database.embedding_provider.id
embedding_model_name = agent.vector_database.embedding_provider.model_name
vector_dimension = agent.vector_database.vector_dimension

# Extract optional LLM config (for reranking)
llm_provider_id = agent.llm_provider.id if agent.llm_provider else ""
llm_model_name = agent.llm_provider.model_name if agent.llm_provider else ""
```

### Step 2: Generate Query Variants

Generate 5 diverse query variants from the user's question:

```python
query_variants = generate_query_variants(user_query)  # Returns list of 5 variants

# Example:
# Original: "How do I configure SSL in Apache?"
# Variants:
# 1. "How do I configure SSL in Apache?"
# 2. "Setting up SSL certificates in Apache web server"
# 3. "Apache HTTPS configuration with SSL"
# 4. "Web server security: SSL/TLS setup"
# 5. "Apache SSL certificate installation steps"
```

### Step 3: Call MCP Tool with Embedding Config

```python
result = await call_mcp_tool("knowledge_expert", {
    # Query variants (pre-generated by supervisor)
    "search_query": query_variants,  # List of 5 variants

    # Collection configuration
    "collection_name": "MyCollection",  # agent.vector_database.collection_name
    "top_k": 5,                         # Number of docs to retrieve
    "user_id": current_user_id,

    # Embedding configuration (REQUIRED - from vector database)
    "embedding_provider_id": embedding_provider_id,
    "embedding_model_name": embedding_model_name,
    "vector_dimension": vector_dimension,

    # LLM configuration (OPTIONAL - for reranking)
    "llm_provider_id": llm_provider_id,
    "llm_model_name": llm_model_name,

    # Tracking
    "conversation_id": conversation_id,
    "conversation_description": conversation_domain,
})

# Result contains ranked documents
documents = result["documents"]  # Already ranked by relevance
```

## Example Implementation

### Python Example

```python
async def handle_user_query_with_rag(user_query: str, agent_id: str):
    """Handle user query using assistant with RAG knowledge retrieval."""

    # 1. Load agent configuration
    agent = await agent_service.get_agent(agent_id, current_user_id)

    if not agent.vector_database or not agent.vector_database.embedding_provider:
        raise ValueError("Agent not configured for RAG retrieval")

    # 2. Generate query variants
    query_variants = await query_enhancement_service.generate_variants(user_query)

    # 3. Extract embedding config from agent
    embedding_config = {
        "embedding_provider_id": agent.vector_database.embedding_provider.id,
        "embedding_model_name": agent.vector_database.embedding_provider.model_name,
        "vector_dimension": agent.vector_database.vector_dimension,
    }

    # 4. Extract LLM config from agent (for reranking)
    llm_config = {
        "llm_provider_id": agent.llm_provider.id if agent.llm_provider else "",
        "llm_model_name": agent.llm_provider.model_name if agent.llm_provider else "",
    }

    # 5. Call MCP knowledge_expert tool
    knowledge_result = await mcp_tools.knowledge_expert(
        search_query=query_variants,
        collection_name=agent.vector_database.collection_name,
        top_k=agent.vector_database.top_k,
        user_id=current_user_id,
        **embedding_config,    # Unpack embedding config
        **llm_config,           # Unpack LLM config
        conversation_id=conversation_id,
        conversation_description=conversation_domain,
    )

    # 6. Use ranked documents to answer the query
    documents = knowledge_result["documents"]

    # 7. Generate answer using documents
    answer = await llm_service.generate_answer(
        query=user_query,
        documents=documents,
        llm_provider=agent.llm_provider,
    )

    return answer
```

### TypeScript Example

```typescript
async function handleUserQueryWithRAG(
  userQuery: string,
  agentId: string,
): Promise<string> {
  // 1. Load agent configuration
  const agent = await agentService.getAgent(agentId, currentUserId);

  if (!agent.vector_database?.embedding_provider) {
    throw new Error("Agent not configured for RAG retrieval");
  }

  // 2. Generate query variants
  const queryVariants = await queryEnhancementService.generateVariants(userQuery);

  // 3. Call MCP knowledge_expert tool
  const knowledgeResult = await mcpTools.knowledge_expert({
    search_query: queryVariants,
    collection_name: agent.vector_database.collection_name,
    top_k: agent.vector_database.top_k,
    user_id: currentUserId,

    // Embedding config (NEW - REQUIRED)
    embedding_provider_id: agent.vector_database.embedding_provider.id,
    embedding_model_name: agent.vector_database.embedding_provider.model_name,
    vector_dimension: agent.vector_database.vector_dimension,

    // LLM config (for reranking)
    llm_provider_id: agent.llm_provider?.id || "",
    llm_model_name: agent.llm_provider?.model_name || "",

    conversation_id: conversationId,
    conversation_description: conversationDomain,
  });

  // 4. Generate answer using ranked documents
  const documents = knowledgeResult.documents;
  const answer = await llmService.generateAnswer({
    query: userQuery,
    documents,
    llmProvider: agent.llm_provider,
  });

  return answer;
}
```

## Error Handling

### Missing Embedding Config

If embedding config is not provided, the retriever will fall back to fetching from collection:

```python
# This logs a warning but continues
logger.warning("Embedding config not provided, fetching from collection...")
```

**However**, for best performance, always provide embedding config.

### Missing LLM Provider

If LLM provider is not provided for reranking:

```python
# Reranking will be skipped
logger.warning("LLM provider not provided, skipping reranking...")
```

**Recommendation**: Always provide LLM provider for consistent reranking.

## Validation Checklist

Before calling the MCP tool, validate:

- [ ] Agent has vector_database configuration
- [ ] Agent.vector_database has embedding_provider
- [ ] embedding_provider.id is not null/empty
- [ ] embedding_provider.model_name is not null/empty
- [ ] vector_dimension is between 1-4096
- [ ] Query variants list has exactly 5 items
- [ ] All query variants are in the SAME language
- [ ] Collection name matches an existing collection
- [ ] User ID is valid
- [ ] Agent has llm_provider (optional but recommended)

## Performance Notes

- **Reranking**: Now enabled by default (+20-50ms latency, +30-50% quality improvement)
- **Embedding Config**: Provided via parameters (faster than DB lookup)
- **Fallback**: Automatic if config not provided (slight latency increase)

---

## Migration Path

### Phase 1: Optional (Backward Compatible)
- Supervisor can skip embedding parameters
- Retriever falls back to fetching from collection
- Reranking works normally

### Phase 2: Recommended (Current)
- Supervisor provides embedding parameters
- Retriever uses provided config (faster)
- Reranking enabled by default

### Phase 3: Required (Future)
- All calls must provide embedding parameters
- Fallback path removed for performance
- Strict validation of embedding config
